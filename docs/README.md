# ATM 习惯打卡 · 手机版（PWA）

在 iPhone 上用 Safari 打开 `https://nikezi623.github.io/AITaskManager/`，
点分享 → 「添加到主屏幕」。之后从主屏幕图标打开，就像原生 App 一样全屏运行。

数据存在私有仓库 `nikezi623/ATM-data`，手机和电脑共用同一份。

---

## 首次设置

1. **添加到主屏幕**：必须走这一步。Safari 标签页里的网页版能看能用，但
   通知、全屏、离线缓存都没有。
2. **填 GitHub 令牌**：点右上角 ⚙ → 粘贴 token → 「保存」→「测试连接」看到
   「连接正常」即可。

令牌只在你的手机本地（localStorage）保存，用来读写你自己那个私有仓库。

---

## 手机上出问题了怎么办

### 页面白屏 / 显示的是旧版本

iOS 的网页缓存很激进，而且手机上**没有开发者工具**可以查。所以设置里有一个
「强制更新」按钮：

⚙ → 「强制更新」 → 它会注销 Service Worker、清掉所有缓存、重新加载。

绝大多数「怎么改都没反应」都是缓存问题，先点这个。

### 打卡没同步 / 右上角圆点是橙色或红色

圆点的意思是：

| 颜色 | 含义 |
|---|---|
| 灰色 | 还没配令牌 |
| 绿色 | 已同步 |
| 橙色 | 有改动待同步 |
| 蓝色（闪烁） | 正在同步 |
| 红色 | 同步失败 |

点底部左边那行「本周完成率」可以立刻手动同步一次。

**红色最常见的原因**：

- **令牌过期或被撤销** —— 会弹出提示，点提示里的「设置」重新粘贴一个
- **网络不通** —— 数据都在本机，网络恢复后会自动补传，不会丢
- **令牌权限不够** —— 需要 `ATM-data` 仓库的 **Contents: Read and write**，
  其它权限一个都不用给

### 数据会不会丢

不会。每次推送前，手机本地会保留最近 3 份快照；云端的每一次同步都是一个
独立 commit，可以逐个回滚。电脑端每次同步前也会把旧的 `task_pool/*.json`
备份到 `.atm/backups/<时间戳>/`。

## 操作方式

桌面版用右键菜单和拖拽，手机上没有这两样，换成了：

| 操作 | 手机上怎么做 |
|---|---|
| 打卡 | 点右边的圆圈 |
| 切换「累计 / 连续」 | 点习惯名右边的 `📊 13` |
| 改习惯 / 删除 / 移动分组 / 上下移 | **长按**那一行（约半秒） |
| 改分组 / 删分组 / 加习惯 | **长按分组标题** |
| 新建习惯或分组 | **长按空白处**，或点右下角 `+` |
| 看全部统计 | 点底部 `📊` |
| 切换中英文 | 点右上角 `EN` / `中文` |

排序用的是菜单里的「上移 / 下移 / 移动到分组」，没有做拖拽 —— iOS 上
HTML5 拖拽不触发，自己写触摸拖拽要处理指针捕获、边缘自动滚动、落点计算，
是个 bug 农场。功能上这几项菜单和电脑端是等价的，因为电脑端本来就有。

## 和电脑端怎么同步

电脑上的桌面程序**不会自动同步**，需要手动跑一次：

1. **先关掉 `AI_TaskManager.exe`**（重要 —— 程序运行时会把内存里的任务列表
   整个覆盖回文件，同步刚拉下来的数据会被冲掉）
2. 双击 `tools\sync.bat`
3. 按提示按键，等它跑完
4. 重新打开程序

手机这边不用管，打开 App 或者从后台切回来时会自动同步。

## 企业微信推送

每天 4 次（06:05 / 12:03 / 18:02 / 21:30，北京时间），由 GitHub Actions 在
云端跑，**不再依赖电脑开机**。

- 以前那个 Windows 计划任务 `ATM_Report` 要删掉，否则会和云端一起推，一天
  收到 8 条
- 推送内容里的「日期」按北京时间算。cron 用的 UTC，06:05 北京对应前一天的
  22:05 UTC，脚本里专门处理过这个
- 想手动测试：Actions 页面 → WeCom Habit Report → Run workflow，
  `dry_run` 默认勾着，只会打印不会真发
- 如果哪天不推了，多半是仓库 60 天没动静被 GitHub 自动禁用了定时任务，
  跑一下 `gh workflow enable wecom-report.yml`

## 在电脑上调试

不需要构建步骤，直接起个静态服务器：

```bash
cd AITaskManager/docs
python -m http.server 8000
# 打开 http://localhost:8000
```

跑测试：

```bash
python tests/test_merge.py        # 合并算法（Python，和 JS 跑同一份夹具）
node tests/test_merge.mjs         # 合并算法（JS）
node tests/test_store.mjs         # 状态逻辑：排序、连续天数、周完成率、删除级联
node tests/test_render.mjs        # 渲染与交互（需要 jsdom）
python tests/test_sync.py         # 电脑端同步的差分逻辑
python tests/test_report.py       # 企业微信消息和桌面端逐字节一致
```

改了 `docs/` 下任何文件后，**记得同时改两处版本号**：`docs/js/main.js` 的
`VERSION` 和 `docs/sw.js` 的 `CACHE_VERSION`。不改的话手机上会一直用缓存
里的旧文件，表现为「改了没生效」。
