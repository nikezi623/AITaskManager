# ATM-data

习惯打卡的数据仓库（私有）。手机上的 PWA 和电脑上的桌面程序都读写这里的
`atm-state.json`，企业微信推送也在这个仓库里定时运行。

## 里面有什么

| 文件 | 作用 |
|---|---|
| `atm-state.json` | 唯一数据源：习惯、分组、打卡记录 |
| `tools/send_report.py` | 生成并推送企业微信报告 |
| `.github/workflows/wecom-report.yml` | 每天 4 次的定时任务 |

## 数据格式（schema 3）

打卡记录按「习惯 × 日期」逐格存储，用一个带符号的时间戳表示状态：

```jsonc
"checkins": {
  "习惯id": {
    "2026-09-16":  1789558507,   // 正数 = 已打卡，绝对值是 epoch 秒
    "2026-09-17": -1789558508    // 负数 = 明确取消打卡（墓碑）
  }
}
```

墓碑是一个**值**而不是一次事件，所以它会被永久保留、在每台设备上都能赢，
这正是「取消打卡」能正确传播到另一台设备的原因。

`habits` / `groups` 里的每条记录都带 `updatedAt` 和 `writer`，合并时按
「时间新的赢、时间相同按 writer 字典序」决定，保证两台设备算出同一个结果。

## 企业微信推送

时间表（北京时间）：

| 时间 | 对应的 UTC |
|---|---|
| 06:05 | 前一天 22:05 |
| 12:03 | 04:03 |
| 18:02 | 10:02 |
| 21:30 | 13:30 |

**注意 06:05 那条**：cron 是 UTC，06:05 北京对应的是**前一天**的 22:05 UTC。
`send_report.py` 因此始终从北京时间取日期，而不是用 runner 上的
`date.today()`。

Webhook 存在仓库的 Actions secret `WECOM_WEBHOOK` 里，**不写进任何文件** ——
手机端读不到它，令牌泄漏也拿不到推送凭证。

### 手动测试

Actions 页面 → WeCom Habit Report → Run workflow，`dry_run` 默认勾选，
只会打印消息不会真的发送。

### 如果推送停了

GitHub 会在仓库**连续 60 天没有 push** 后自动禁用定时工作流。手机端每天打卡
都会产生 commit，正常使用不会触发；万一被禁了，重新启用：

```bash
gh workflow enable wecom-report.yml
```

或者在 Actions 页面点那条黄色横幅里的 "Enable workflow"。

## 两台设备同时改会怎样

数据是每天在手机上打卡、电脑上偶尔补记。合并规则是：

- **不同的打卡格子** —— 两边都保留，不会互相覆盖
- **同一个习惯、同一天** —— 时间戳新的赢。所以取消打卡不会被旧数据"复活"
- **同一条记录（习惯名/分组）在两台设备上都被改过** —— 后改的赢

最后一条是唯一会"丢"的情况，但那是正确的语义：一个人自己的习惯清单，
后改的意图就是最新意图。不会出现需要手工解决的冲突。

## 怎么恢复数据

每次推送前，手机端会在本机保留最近 3 份快照。电脑端每次同步前会把旧的
`task_pool/*.json` 备份到 `AITaskManager/.atm/backups/<时间戳>/`。

如果云端数据被改坏了，这个仓库的每一次写入都是一个 commit，直接看历史回滚：

```bash
git clone <this repo>
git log --oneline -- atm-state.json
git show <commit>:atm-state.json > atm-state.json
```
